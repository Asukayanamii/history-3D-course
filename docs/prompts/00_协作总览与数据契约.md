## 1. 目标与边界

**本轮目标**：做出一个能双击打开、能给老师演示的「3D 历史沙盘骨架」，覆盖 PRD 中 F1–F4 的全部效果，以及 F5.1、F7.1–F7.4 的至少一次演示。

**三个时期**：

| 主题 ID | 显示名 | Demo 事件线 | 定位 |
|---|---|---|---|
| `wudai` | 五代十国 | 后周世宗与统一前夜（907–960） | **默认、重点演示**，数据最完整 |
| `suitang` | 隋唐 | 安史之乱（755–763） | 薄主题，3–6 个事件，证明可切换 |
| `song` | 宋朝 | 澶渊之盟（1004–1005） | 薄主题，3–4 个事件，证明可切换 |

**本轮做**：1 个「兵棋推演」场景（五代十国 `e06` 高平之战：省份控制 + 兵力/士气 + 自动战斗 + 派生战线），其余事件保留「进入场景（待补）」禁用入口。

**不做**：完整 F6 场景库、第一人称/VR、真实 DEM 地形、移动端适配、完整 12 事件素材库、背景音乐版权素材。后续场景按 F6 契约扩展。

**Demo 的诚实原则**：所有历史边界都是示意性简化，所有 AI 插画都是艺术复原示意；未核订的内容必须在数据与 UI 中标记为占位。

### 5.1 字段约束

- `routeId` / `nodeId` 必须能在同一主题的 `routes` 中找到；找不到时引擎应回退到事件经纬度并 `console.warn`，不能崩溃。
- `event.lon` / `event.lat` 必须落在 `map.bounds` 内；DeepSeek 要逐条校验。
- `regions[].polygon` 允许为空。为空时引擎用 `labelAt + radiusKm` 生成示意 blob；**这比编造精确边界更诚实**。
- `polygon` 有值时：至少 3 个点、顺时针、不自交、不与地图边界相交；`status` 必须为 `approx` 或 `reviewed`。
- 五代十国至少 6 个主要政权（后周、南唐、吴越、后蜀、南汉、契丹）应有简化多边形；其余可用小多边形或 blob。所有多边形标 `approx`，不得声称精确。
- `map.mapSnapshot` 必填；`map.omitted` 列出未单列势力；图例显示。
- `regions[].highlight` 为 true 时建议写 `highlightReason`（为什么重点：战争/改革/教材要求），图例显示。
- `events[].figures` / `result` / `impact`：有 `scene` 的事件必须有；其他事件建议补，缺失时 UI 显示「待补」，不得编造。
- `sources[].url` 只填**实际可访问**的链接；不确定就留空，并在 `note` 写“待核实”。禁止编造 DOI、页码、URL。
- `historiography.level`：`consensus`（教材共识）、`debate`（学界争议）、`tradition`（后世传说/文学叙述）、`uncertain`（存疑）。有争议的事件必须在 `note` 说明。
- `meta.status` 与 `events[].status` 的关系：主题级 `reviewed` 要求所有事件至少 `sourced` 且历史审核通过；Demo 阶段允许 `placeholder`。

### 5.2 多路线与时间轴

- 一个主题可以有 1–3 条路线。事件通过 `routeId + nodeId` 指向路线节点。
- 事件顺序由 `events[].order` 决定，不由路线几何顺序决定。
- 切换事件时：同一条路线则从当前进度补间到目标节点；换路线则旧路线淡出、新路线从 0 生长到目标节点。进度允许后退。
- 多个事件可以共享同一节点（例如后梁、后汉、后周都在汴州）；共享节点时路线进度不变，卡片正常切换。

### 5.3 主题切换

- 切换主题时：关闭卡片/问答/来源弹窗 → 淡出旧场景 → dispose 旧几何/材质 → 用新主题重建 → 相机飞到 `meta.home` → 打开 `defaultEventId` 的卡片。
- 主题切换不得刷新页面，不得依赖网络。
- URL 参数：`?theme=wudai&event=e01&demo=1&dwell=8000&nointro=1`。非法值回退到默认主题/第一个事件，并在控制台说明。

- `phases[].effects` 只做 `morale` / `attack` 等轻量修正；不要直接改 `owner` 或战线。
- 同一 `seed` + 同一数据必须得到同一结果；`goToPhase` 用重置 + 固定步长快进实现。
- 场景必须明确「战术示意，不是精确历史阵图」；AI 声明仍由主页统一承担。
- 时期选择器按起始时间：`["suitang", "wudai", "song"]`，默认 `wudai`；快捷键 `1/2/3` 对应隋唐/五代十国/宋朝（场景内改为速度 1x/2x/4x）。

```js
      path: "assets/events/wudai/e01.jpg",
      spec: "1920x1080 JPEG, sRGB, 16:9, no text/watermark",
      provider: "gpt-image2",         // gpt-image2 | deepseek | human | claude
      priority: "P0",                 // P0 | P1 | P2
      status: "missing",              // missing | placeholder | ready | needs-review
      promptDoc: "docs/history/五代十国_图片脚本.md",
      usedBy: ["theme.wudai.js#e01"],
      note: ""
    }
  ]
};
```

**状态语义**：

| 状态 | 含义 | UI 表现 |
|---|---|---|
| `missing` | 文件不存在 | 卡片显示设计过的占位图，不显示破图 |
| `placeholder` | 有占位内容，不可用于正式教学 | 显示「占位 · 待替换」角标 |
| `ready` | 文件存在且规格合格 | 正常显示 |
| `needs-review` | 文件存在但内容/规格待审 | 正常显示 + 小角标 |

`assets.js` 由 Claude 第一轮生成，DeepSeek 不修改；GPT-Image2 交付图片后可把对应条目的 `status` 改为 `ready`，并在 `note` 写生成日期/模型。Claude 第二轮负责最终核对。

> `provider` / `promptDoc` / `note` 只用于团队内部追溯，**不要求展示在 UI**。AI 生成图不需要逐张标来源，主页/页脚统一声明即可；外部网站/地图来源才需要在「来源与授权」里逐项列出。

### 10.1 来源标注规则

**原则：用了别人的网站、地图、史料，就要能追溯；AI 生成的图片不需要逐张标来源，只在主页/页脚统一声明一次。**

## 12. 换主题/换选题的操作

- **换事件/换路线**：只改 `data/theme.<id>.js` 的 `events`、`routes`、`timeline`；`meta.defaultEventId` 指向第一个事件。
- **换时期**：新增 `theme.<id>.js`，在 `themes.index.js` 的 `HISTORY_THEME_ORDER` 里加 ID；顶栏自动出现新标签。
- **换地图范围**：改 `map.bounds`；所有经纬度会重新投影；检查 `polygon` 是否越界。
- **换视觉**：改 `meta.accent` 和 `regions[].color`；不要改引擎的布局结构。
- **换图片**：按命名规则放入 `assets/events/<主题>/<事件>.jpg`，把 `assets.js` 的 `status` 改为 `ready`；卡片自动显示。
