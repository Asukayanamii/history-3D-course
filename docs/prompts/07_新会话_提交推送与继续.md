## 第二步：继续补 e06 高平之战 war 场景的路线轨迹指示线

### 现状

- `course/js/scene.js#warBuildRoutes` 已经会为 e06 单位的跨省 orders 生成路线：普通移动是 `TubeGeometry` + 终点圆锥，撤退是虚线。
- `warUpdateVisuals` 只在 `t >= start && t <= end` 时显示整条路线；路线是静态的，出现时已经画满，没有“随单位移动生长”的轨迹感，而且线偏细、在 DEM 上不够醒目。
- 用户要的是：**与 e06 战争场景对齐的路线轨迹指示线效果**，不是另画一条与单位无关的装饰线。

### 目标

只改 e06 所属的 `war` 渲染路径，给当前行动路线加“生长轨迹 + 发光 + 箭头头部”：

1. 路线仍然来自 `warBuildRoutes` 的 `orders`，不要新造路线数据。
2. 当前行动段（`u.moving` 且 `u.target` 对应 `to`）：
   - 用 `u.moveT`（0–1）控制轨迹的可见长度；
   - 推荐对 `TubeGeometry` 的 `geometry.setDrawRange(0, n)` 做部分显示，或用等价的确定性方式；
   - 箭头/头部放在当前轨迹末端，朝向曲线切线；到终点后停在终点。
3. 单位到达后，在当前 order 时间窗内保留完整轨迹；时间窗结束后隐藏。
4. 普通移动：阵营色核心线 + 加法混合的宽光带 + 移动箭头。撤退：冷色虚线/低透明度 + 反向头部，保持“撤退”语义。
5. 每帧更新轨迹时不要新建大量几何/材质/数组；复用 `routeObjs` 中的 `curve/core/glow/head`。
6. 保留 `routes` 图层开关；关闭后路线和头部一起隐藏，打开后当前帧状态正确。
7. 不改 e06 的省份、owner、`warUpdateControl`、`warRebuildFront`、终局 7/1/1；不改 battle/court。
8. 路线仍是战术示意；如果 UI 有空间，补一句“路线为当前行动方向，战术示意”，不要写成精确行军路线。

### 建议实现点

- `warBuildRoutes`：
  - 为每条路线保存 `curve`、`core`、`glow`、`head`、`from`、`to`、`start`、`end`、`unit`、`type`。
  - `TubeGeometry` 分段数提高到 24 左右；核心半径约 0.24–0.28，光带约 0.6–0.8，`depthWrite:false`。
  - 头部用 `ConeGeometry` 或小箭头，按曲线切线定向；`renderOrder` 高于省份/边界，低于单位头标。
  - 初始 `setDrawRange(0, 0)`，由 `warUpdateVisuals` 更新。
- `warUpdateVisuals`：
  - 根据当前 `t` 和 `r.unit.moving / target / moveT` 计算 `progress`；
  - 设置 core/glow 的 draw range；
  - 头部位置 `curve.getPoint(progress)`；到达终点后保持；
  - 光带做轻微脉冲，但不要用 `Math.random()`；
  - 路线隐藏时同时隐藏头部。
- 不要使用 `LineDashedMaterial` 的 `linewidth` 做主线（浏览器 WebGL 不支持稳定宽度）；撤退可用虚线，但主行动线用 tube。
- 如果实现 draw range 后某些显卡上出现截断三角形，改用“按进度重建少量 tube”或“沿曲线放置箭头”的确定性方案，但不要退回每帧重建整条路线。

### 验收

1. e06 进入 war 场景，`routes` 图层默认开启。
2. `t=0.1 / 0.35 / 0.65 / 1.0` 分别截图：
   - 北汉南下、高平接战、后周反击、收束阶段的路线方向和阵营色正确；
   - 轨迹随单位移动生长，不是一次性整条出现；
   - 箭头头部清晰，1920×1080 与 1366×768 都能辨认；
   - 撤退路线与进攻路线可区分。
3. `routes` 图层关闭/打开有效；关闭后无残留头部。
4. e06 终局仍为后周 7 省、北汉/辽各 1 省；省份、战线、单位牌正常。
5. `node --check course/js/scene.js`；`git diff --check`；console 无 error；无外部 `http(s)` 请求。
6. 更新 `docs/handoff/WAR_SCENE_SPEC.md` 或 `docs/handoff/CODE_NOTES.md`，写清“路线轨迹是当前行动方向 + 与 unit.moveT 对齐”，以及“不是精确行军路线”。
7. 新改动先不要提交/推送，等用户明确要求；如果用户要求，再按同样规则提交。
